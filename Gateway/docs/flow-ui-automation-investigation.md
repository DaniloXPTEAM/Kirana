# Investigação: automação open source do Google Flow Web

**Verificado em:** 2026-10-24. **Escopo:** avaliação estática de READMEs, documentação, licenças, código-fonte público e ajuda/termos oficiais. Nenhum repositório foi clonado, instalado ou executado; nenhuma sessão Google foi acessada; nenhuma geração, download de mídia, chamada paga ou consumo de crédito/cota foi realizado.

## Resultado executivo

**Nenhum dos quatro projetos está aprovado para integrar ou executar agora**, diante das exigências de não contornar CAPTCHA, login, limites ou outras proteções e de não submeter geração sem autorização específica.

O candidato funcionalmente mais forte no momento da consulta é `ffroliva/gflow-cli` (v0.89.1; atividade até 24-10-2026), com evidência publicada pelo mantenedor de uso real da UI do Flow e downloads. Porém, o próprio projeto declara que usa superfície REST privada/reverse-engineered, inclui mecanismo opcional de evasão de reCAPTCHA Enterprise (`patchright`), recomenda jitter de interação e descreve alternar perfis como estratégia após bloqueios. Não é aceitável integrar o projeto sem modificações sob as restrições atuais.

`swissmarley/gflow-cli` é o candidato conceitualmente mais próximo de automação do UI sem API privada: declara operar o Chrome do usuário, não resolver CAPTCHA, não contornar login e não evadir rate limits. Há relatos documentados pelo próprio repositório de gerações reais de imagem/vídeo e download. Ainda assim, o último commit observado é de 10-06-2026; uma issue aberta de 02-10-2026 relata incompatibilidades com a migração para `flow.google.com`, além de problemas Windows/idioma. A versão atual não foi validada e o modo `--no-headed` opera com Chrome oculto/minimizado. Também não há confirmação oficial do Google autorizando essa automação.

O `google-flow-mcp` explicita que inicia Chrome para que `navigator.webdriver` seja falso, chamando isso de medida anti-bot; portanto é incompatível com a proibição de contornar proteções. `flow-api-client` faz chamadas HTTP a RPCs internos reverse-engineered, extrai credenciais/sessão via CDP e avisa que o uso viola os termos; excluir.

## Termos e controles oficiais consultados

- Os [Google Terms of Service](https://policies.google.com/terms?hl=en) (vigentes desde 30-07-2026 na página consultada) proíbem abuso, interferência e bypass de sistemas ou medidas protetivas; também proíbem meios automatizados de acesso quando violam instruções machine-readable das páginas (por exemplo, `robots.txt`). O texto consultado não é uma autorização específica para automação do Flow.
- A ajuda oficial do [Google Flow](https://support.google.com/flow/answer/16353333?hl=en) diz que geração pode ser rate-limited, especialmente modelos de custo zero; depois de muitas gerações diárias, o limite por minuto pode cair. Em casos de “unusual activity”, recomenda esperar ou desativar VPN/proxy — não ensina a contornar bloqueios.
- A ajuda exige elegibilidade de conta/plano/região, e custos correntes devem ser conferidos no seletor do próprio Flow. Não tratar imagens como grátis nem pressupor que uma assinatura/crédito autoriza automação.
- [Google Flow](https://labs.google/fx/tools/flow) está protegido por reCAPTCHA; o `robots.txt` de `labs.google` que foi lido permite crawl genérico, mas isso não constitui autorização para automatizar ações autenticadas do Flow. A tentativa de ler `flow.google.com/robots.txt` retornou a página protegida/reCAPTCHA, portanto sua instrução machine-readable não foi confirmada. Não se tentou resolver o desafio.
- A ajuda diz que os termos do Google governam o uso do Flow; não foi localizada uma autorização oficial específica para Playwright/CLI/MCP nem uma API pública de geração Flow com contrato de retorno de arquivo.

## SIWC: áudio, streaming e voz

A documentação SIWC consultada define uso do plano ChatGPT no endpoint público `https://api.openai.com/v1/responses`, com `store:false` e `stream:true`; proíbe assumir ou apontar para endpoints `backend-api` do ChatGPT. As limitações excluem entrada de áudio/vídeo, upload Files, transcrição e várias ferramentas hospedadas. Não há rota de geração de áudio/TTS descrita nesse contrato. A API Realtime e `/v1/audio/speech` são rotas/documentação separadas; **não** usar nelas o token SIWC nem inferir que o direito SIWC de Responses as autoriza. Até haver documentação SIWC explícita, manter TTS Piper local e transcrição Whisper.cpp local como estão; não alterar SIWC textual.

Fontes oficiais: [SIWC Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) · [SIWC Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) · [Realtime API docs](https://developers.openai.com/api/docs/guides/realtime) (produto/rota separada; não prova acesso via SIWC).

## Decisão de integração e critérios de reabertura

1. Nenhuma geração ou instalação agora: não há sessão Google ligada ao sandbox, e a permissão de executar/cobrar crédito não foi concedida para uma tentativa específica.
2. Não usar rotas internas, cookies/tokens capturados, stealth/`navigator.webdriver` patching, `patchright`, proxies/IP rotation, randomização para driblar detecção, rotação de perfis/contas ou qualquer contorno de CAPTCHA/login/rate-limit.
3. Para reavaliar `swissmarley/gflow-cli`, aguardar versão que reconheça o host atual e demonstrar revisão do código estático; manter Chrome visível e ação manual de verificação se o Flow pedir. Ainda é necessária autorização explícita do Google ou confirmação oficial de que a automação é permitida; um aviso do mantenedor não substitui isso.
4. Se houver caminho permitido, a integração deve exigir aprovação humana imediatamente antes de cada submissão, mostrar modelo/custo estimado/créditos e parar diante de CAPTCHA, verificação, consentimento, bloqueio, limite ou diálogo inesperado; nunca repetir automaticamente uma submissão incerta.
5. Só então pedir autorização pontual para operação que possa gastar cota/créditos; realizar teste real de uma imagem, confirmar o tile novo no projeto e recuperar bytes do download oficial. Registrar conta sem identificador sensível, modelo, custo/cota mostrado, resultado e hash/validação do arquivo.
6. Não modificar Gateway, SIWC textual, Kirana ou baseline enquanto essa autorização e o caminho compatível não estiverem estabelecidos.
